# 모두의 뇌 Design Skill

이 문서는 `모두의 뇌` 화면을 계속 만들 때 반복해서 적용할 나만의 디자인 규칙이다. 목적은 디자인 결과가 예쁘기만 한 화면이 아니라, 서비스의 차별점인 협업 맥락 공유를 분명히 보여주도록 유지하는 것이다.

## 0. UI/UX Pro Max 적용 방식

- UI 작업은 설치된 `ui-ux-pro-max` 스킬로 제품 유형, 접근성, 상호작용, 반응형 기준을 먼저 점검한다.
- 프로젝트의 최종 source of truth는 `design-system/modu-brain/MASTER.md`다.
- 스킬의 범용 추천이 기존 브랜드 결정과 충돌하면 모두의 뇌의 차분한 블루, 근거 중심 정보 구조, 시스템 한글 폰트를 우선한다.
- 구현은 `src/styles.css`의 의미 기반 CSS 변수로 연결하고 컴포넌트 안에 임의 색상과 모션 값을 늘리지 않는다.
- UI 전달 전 키보드 탐색, focus-visible, 44px 터치 영역, 375/768/1024/1440px, reduced motion, 로딩·오류 상태를 확인한다.

## 1. 핵심 판단 기준

디자인을 수정할 때마다 다음 질문을 먼저 확인한다.

1. 이 화면이 회의 요약 앱처럼 보이지 않는가?
2. 사용자가 `관점 차이`, `미결 질문`, `결정 배경`을 먼저 볼 수 있는가?
3. 새 팀원이 이 화면만 보고 프로젝트 현재 상태를 이해할 수 있는가?
4. 장식보다 실제 UI 흐름이 더 잘 보이는가?
5. 모바일에서도 텍스트와 카드가 깨지지 않는가?

## 2. 화면 구성 규칙

- 홈 화면은 서비스 설명보다 문제 상황을 먼저 보여준다.
- 입력 화면은 사용자가 어떤 자료를 넣어야 하는지 명확해야 한다.
- 결과 화면은 요약문보다 참여자별 관점 표와 미결 질문을 우선 배치한다.
- 지식맵 화면은 복잡한 그래프보다 이해 가능한 연결 구조를 우선한다.
- 온보딩 요약 화면은 새 팀원에게 바로 공유할 수 있는 문장으로 구성한다.

## 3. 스타일 규칙

- 배경은 `#f5f5f7`, 카드와 패널은 `#ffffff`을 기본으로 사용한다.
- 포인트 컬러는 `#0066cc` 하나로 통일한다.
- 카드와 입력창 radius는 `8px`로 유지한다.
- 버튼과 탭은 `999px` pill 형태를 사용한다.
- 한 화면에서 색을 많이 늘리지 않는다.
- 그림처럼 보이는 AI 이미지는 피하고, 단순한 노드/선/표 구조로 표현한다.

## 4. 컴포넌트 규칙

- 버튼은 `Primary`, `Secondary`, `Disabled` 세 상태만 먼저 만든다.
- 결정사항은 상태 배지로 구분한다: `확정`, `논의중`, `불확실`.
- 지식맵 노드는 역할별로 구분한다: `주제`, `사람`, `결정`, `질문`.
- 탭은 `개요`, `지식맵`, `온보딩 요약` 세 개로 고정한다.
- 입력 패널과 결과 패널은 같은 border, radius, padding 규칙을 사용한다.

## 5. 피드백 반영 규칙

디자인이 마음에 들지 않을 때는 전체 스타일을 바꾸기보다 다음 순서로 수정한다.

1. 화면에서 가장 먼저 보여야 할 정보가 맞는지 확인한다.
2. 카드 간격과 제목 크기를 조정한다.
3. 강조 색 사용이 과한지 확인한다.
4. 텍스트가 길어져도 레이아웃이 유지되는지 확인한다.
5. 마지막에 장식 요소를 줄인다.

## 6. 개발 Agent 전달 문장

개발 Agent에게 디자인을 전달할 때는 다음 문장을 함께 사용한다.

> 이 디자인은 회의 내용을 짧게 요약하는 앱이 아니라, 프로젝트의 결정 배경, 사람별 관점 차이, 미결 질문을 구조화하는 협업 맥락 에이전트 화면이다. 따라서 결과 화면에서는 단순 요약보다 관점 표, 미결 질문, 지식맵을 먼저 보여줘야 한다.
